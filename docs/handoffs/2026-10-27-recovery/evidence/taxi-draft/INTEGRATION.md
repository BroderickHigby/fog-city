# Taxi reducer draft — scratch only

Drafted against the parent's fetched `origin/main` baseline `66b1e6f51fd1799612d6319980fca7f2241b17a9` and the local `codex/consolidated-game-upgrade` SIM21 integration. These files have not been copied into production, compiled, executed, or browser-tested. Production remained frozen during this work.

## Files and API

- `taxi.ts` → intended `src/sim/modes/taxi.ts`: `createTaxiState(config,start)`, `stepTaxi(previous,config,acceptedContext)`, `taxiView(state,config)`, `taxiSettlement(state)`, `taxiConfigHash(config)`.
- `taxi.test.ts` → intended `tests/sim/modes/taxi.test.ts`: unexecuted Vitest source for actual pickup/dropoff safety, exact fare, retry/ID ledger, replay, timeout, blocked route, vehicle continuity, shift limits, JSON restore, immutable input and catalog drift.
- `taxi-session.ts` → intended `src/modes/taxi-session.ts`: complete detached campaign checkpoint, fresh mode SimState, accepted car/human/animal hull observations, exact posted protected passenger binding, and existing once-only city settlement adapter.
- `taxi-session.test.ts` → intended `tests/modes/taxi-session.test.ts`: unexecuted checkpoint isolation, campaign preservation, settlement replay, accepted-physics cadence and autonomous-ride rejection cases.
- No dependencies, network-mode changes, rendering, campaign writes, actor movement, global clock or random source are introduced by the draft.

`TaxiConfig` carries immutable, validated SF routes and themed shift itineraries. The provisional title defaults to **Crazy Uber** and is presentation-only. Route/shift selection is deterministic from the supplied seed. Each session has a durable globally unique taxi-prefixed run ID (simple ID, at most 40 characters, matching the existing city settlement contract), unique attempt ID, fare ID and protected passenger ID. The authored itinerary is rotated by seed and retry number; it then cycles in authored order.

The ordinary loop is waiting passenger → continuous safe stop → fresh Interact edge → drive to destination → continuous safe stop → fresh Interact edge → once-only fare and remaining-time bonus → explicit Next. Default safe-stop time is 120 fixed 60 Hz ticks, default pickup timeout 90 seconds, shift five minutes, route-specific trip time, and route-block grace ten seconds. A premature held Interact must be released and pressed again once stopped. Commands carry only sequence and kind, never positions/completion/reward claims. A last-tick valid dropoff pays base fare with zero bonus. Blocking suspends the pickup/trip clock for a bounded grace period while the shift clock continues. Unknown or mismatched route validation fails closed. Reopening resets stop progress. A blocked waiting passenger may be skipped; a boarded passenger requires retry/cancel/exit recovery.

## Controller ownership and campaign preservation

Keep this as a local gameplay mode controller unless the shared contracts owner explicitly chooses to expand `ModeId`; it is not a network match. Existing match/session concepts are useful for ownership and settlement, but taxi does not need relay/team/combat state.

On entry, retain a complete campaign snapshot and run a separate simulation/session. Preserve the entire campaign: player/vehicle pose and ownership, balances, mission progression, faction clocks, weather/time, inventory, actors and mode settlement ledger. Restore that exact campaign snapshot on exit and then apply the aggregate `taxiSettlement` through the existing durable settlement ledger using its stable `runId:playerId` ID. `taxiSettlement` may be offered repeatedly and deliberately does not mutate the campaign. Campaign application must consume that ID once. A save/reload or graphics-restart checkpoint must include both isolated taxi state and the original campaign snapshot, rather than replacing the original snapshot with in-mode state. Failed attempts preserve the earned fare ledger; retry IDs prevent a replayed fare ID from paying again. Exit finalizes the run; retry after exit is intentionally unavailable. A new run requires a new durable run ID.

The parent should attach the session to its canonical save/replay boundary and validate restored state against the catalog. JSON roundtrip of valid output is supported; this draft does not treat arbitrary imported JSON as trusted state. Persist the paid-fare IDs, totals, attempt/trip counters, command cursor, Interact edge, stop baseline and clock values. Retain the new sim-version boundary already being integrated by the parent if final contracts require it.

## Accepted world observations

The physics/session adapter must produce `TaxiContext` from accepted post-collision state each contiguous tick. `vehicle` must represent the local player's actual manually controlled vehicle; being a rider, standing near a vehicle, or supplying an input position cannot satisfy pickup/dropoff. Require grounded, off-water, low longitudinal/lateral speed and real hull clearance from protected humans and animals. The draft checks position, height, heading continuity, speed and clearance, and locks the boarded vehicle ID until fare completion. The adapter must retire a destroyed/lost vehicle binding through the recovery path.

`waitingPassengerId` must be the actual live mode actor binding. Use the shipped Rocketbox human model and established protected-human placement/clearance rules. Place the passenger safely at a supported curb, outside the vehicle hull safety buffer but within the intended pickup interaction. Retire old mode passenger bindings on next/retry/exit without changing campaign actors. Only hide/board that actor after the reducer emits `taxi.picked-up`; only retire the boarded fare after the accepted `taxi.paid` event or an explicit recovery transition. Rendering never invents a completion event.

The route catalog must use measured road-supported curb coordinates and directed legal paths in real named SF districts. The fixture coordinates in the test are synthetic. Validate pickup and destination zones against the exact world graph, support height, water, road clearance, occupied lanes and protected actors. Validate itinerary transitions and wrap-around. `roadDistanceM` is a checkable declared measurement, not proof of graph reachability. Derive route blocking from the deterministic path/world producer; a UI flag cannot assert a road is clear. Traffic signals, queues and road occupancy remain authoritative.

## UI and presentation

Expose start, shift/theme choice and title in the existing mode selector; use existing day/night/fog/rain systems for the shift theme. Display passenger pickup or destination, remaining trip/shift time, fare total, safe-stop progress and the concrete recovery reason returned by `taxiView`. Provide explicit Next, Retry, Cancel and Exit actions routed through monotonic command sequences. Suppress stale commands on transitions; do not replay a later queued action implicitly into a new attempt. HUD should use the same keyboard/controller mapping as physical Interact. Exit during a fare keeps earlier earnings and earns no unfinished fare.

## Limits and final verification still required

The draft bounds paid fares (256), retries (10,000), and trip slots per attempt (4,096); a session ends safely at capacity. Catalog geometry, rules and rewards are content-hashed on every step to reject mid-session simulation changes. That is simple and safe for a small catalog; the parent may prepare a frozen validated catalog/hash once to avoid repeated sorting/hash work, provided restored sessions still reject mismatches. Labels/title do not affect the simulation hash. Same-sequence conflicting commands use a stable lexical kind tie-break; normal input should never emit conflicting commands with the same sequence.

Before acceptance, copy/integrate only after the parent releases the source freeze, compile, run the meaningful tests and canonical replay suite, validate actual SF routes and actor clearance, and exercise success, timeout, blocked recovery, retry, next and exit through the final browser/game controls. Verify wallet settlement once across save/reload, graphics restart and repeated exit handling, and byte-equivalent restoration of campaign fields other than the authorized settlement. This draft makes no runtime acceptance or route-validity claim.

## Production integration handoff (source thawed)

Backend files have now been copied into the owned production paths. The parent ran one focused test window: the reducer cases passed; the session test's starting-wallet assumption was corrected to assert an earned delta, and the one `CombatWave` typing issue was corrected. Additional route/checkpoint/controller work after that window has not yet been run by this worker. No build/browser/physical acceptance is claimed.

Use these hooks from main (shared file remains parent-owned):

1. Construct `const taxiTick = createSfTaxiStepper(world)` once after loading the exact world.
2. Enter with `createSfTaxiSession(world, city, { id: durableUniqueTaxiRunId, playerId, seed, shiftId: 'day' | 'night' | 'fog-rain' }, { wave, title: 'Crazy Uber' })`. IDs must be simple ASCII identifiers at most 40 chars. Persist a monotonic run counter before entering. The mode enables at least wave 3 internally for real weather, even if the campaign currently occupies an earlier wave; only curbs supported by actually loaded tiles can be selected.
3. Pause city simulation/autosaves. Display the returned `session.instance`. The session contains a detached exact `session.campaign` and fresh mode physics. Do not write mode fields or incidental in-mode activity earnings into the campaign save.
4. Each normal fixed tick call `taxiTick(session, inputFrame, commands, simEvents)` and install its `.instance` for rendering. Keyboard/controller Interact remains the ordinary `Action.interact`. Buttons enqueue only `{ sequence, kind: 'next'|'retry'|'cancel'|'exit' }` using a monotonic per-run cursor. Clear consumed command queues. A fresh Interact after a continuous two-second safe stop boards or drops off. Pre-admission, posted passenger identity, all physical movement and person safety stay under the ordinary core systems.
5. Project `taxiSessionView(session)` for title, current route/district labels, actual target point, clock values, safe-stop progress, recovery reason, `canNext`, and `canRetry`. Show `session.taxi.totalCashCents`, `.totalXp`, `.completedFares`, `.phase`. Marker target comes from view.target, not a command. Retry creates a fresh physical mode attempt at the next seed-selected supported pickup lane; city and earned fare ledger are retained.
6. When `.taxi.phase === 'exited'`, call `settleTaxiSession(session)` and install its `.restored` as the city. Save that city once. This restores every entry field first and adds only the stable aggregate payout via existing `applyMatchSettlement`; do not apply separate fare payments.
7. Save `encodeTaxiSession(session)` alongside graphics-restart metadata. It now emits a bounded schema/checksum/session envelope. At startup call `decodeSfTaxiSession(text, world)` and resume its `.instance`, with `.campaign` still retained. The decoder rejects stale graph edge IDs, content drift, malformed counters/IDs/body shapes and corrupt checksums. If it rejects a mode checkpoint, recover the independently retained normal campaign save and explain the mode could not resume.

`prepareSfTaxiSession` and `advanceTaxiSession` remain available if main needs to compose extra ordinary systems itself. `stepSfTaxiSession` is a convenient uncached reference path; the browser should prefer the cached factory. `createSfTaxiCatalog` measures legal directed paths and a closed curb circuit at entry; every destination equals the next pickup, including wrap-around. `taxiPhysicalRouteStatus` treats stationary solid vehicles occupying the actual stop as blocked and never grants clearance through them.
