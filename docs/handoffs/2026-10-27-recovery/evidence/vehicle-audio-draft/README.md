# Vehicle and recorded audio integration — current handoff

Production integration is now in src/render/vehicle-models.{ts,json}, model-registry.ts, agent-layer.ts, the meshopt-enabled model loader in scene.ts, src/audio/vehicle-recordings.ts, vehicle-recording-manifest.json, vehicle-sound.ts, mixer.ts and the vehicle portion of audio/index.ts. The parent owns index.ts again for opening narration. No main.ts hook is needed: the existing recursive model listing discovers models/vehicles/*.glb. No simulation traffic/collision fields were changed.

Five independently shaped CC0 models (compact hatch, sedan, SUV, pickup, van) total 1,075,572 bytes and 2,032–2,474 triangles each. Exact source/output hashes, license, normalization and dimensions are in assets/imports/vehicle-families/. Each family's actual four hubs, circular wheels, wheelbase and paint contract are tested from the real GLB. Separate near/far family batches respect the existing draw-call budget, including when no crowd renderer exists. The current player fastback remains the missing-family fallback.

Recorded audio uses five prepared layers from four named CC0 source recordings; two engine sections share one recorded car. Ten Ogg Opus/MP3 outputs total 532,422 bytes. Source previews remain explicitly lossy candidates. Exact provenance, trim/crossfade/level parameters and output hashes are in assets/imports/vehicle-audio/. The live driving oscillator is not instantiated. Recorded layers inherit the effects bus/mute/voice ducking, and handle occupied-car identity, cabin mode, pause, visibility, restore, decode/fetch failure, explicit retry and disposal. Source count is capped at eight, decoded buffers at 16 MiB. Missing files remain silent; no synthetic motor/noise replacement is generated.
