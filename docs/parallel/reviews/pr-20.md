## Independent review (coordinator): mergeable after fixes

I reviewed the code itself with read-only git; nothing was run. The four findings marked *checked* I confirmed at the cited lines. This PR's relay also contains #5's Server-Net code (f471347 and b788d11), so **#20 is the recommended basis for online play, and #5 should close.**

**What holds up**
- **Room codes:** 10 characters from a 32-letter alphabet using `randomBytes` (about 50 bits). They expire after 30 minutes, and a fifth player is refused.
- **Messages:** a closed set capped at 4 KB. Clients can't set a player id, send state or chat. Command fields take only id-like values.
- **Names and events:** display names come from a fixed list on the server. Join and leave enter the sim as ticked `SimEvent`s.
- **Rollback and hashes:** rollback is capped at 8 ticks, and a hash goes out every 60 ticks.
- **Cleanup, deploy and tests:** timers and sockets are cleaned up on close, the deploy config has no secrets, and the tests use loopback only.

**Fix before merge**
1. **medium**, `server/net/room.ts:90-94` (checked)
   - **Problem:** a full-state snapshot goes to every client every 60 ticks, whether or not that client diverged.
   - **Failure:** the snapshot silently repairs any client that falls out of sync, so a determinism bug is never detected. On the `sf` world this is a full-state download every second, which can fill the 1 MB send buffer and kick slow clients.
   - **Fix:** send a snapshot only on a resync request or a hash mismatch, and count mismatches.
2. **medium**, `server/net/server.ts:59`, `:100`, `:133`
   - **Problem:** there is no cap per IP, and a room is removed only when it is empty.
   - **Failure:** one script can open 8 rooms with idle sockets and lock everyone else out with `server_full`.
   - **Fix:** cap sockets and rooms per IP, give every room a hard maximum lifetime, and remove members who send no input.
3. **medium**, `tests/net/prediction.test.ts:88` (checked)
   - **Problem:** `resyncs >= 2` has no upper bound, and messages are copied with `structuredClone` instead of JSON.
   - **Failure:** a sim that diverges every second still passes, so the test doesn't prove "identical hashes".
   - **Fix:** assert exactly the injected divergences, and round-trip messages through `JSON.stringify` and `JSON.parse`.
4. **medium**, `src/sim/modes/systems.ts:27` (checked)
   - **Problem:** `payouts: []` is reset on every tick after settlement.
   - **Failure:** payouts exist for exactly one tick, so they're lost if the client runs several ticks in one frame.
   - **Fix:** keep the payouts on the settled session; the settlement ids already remove duplicates.

**Low**
- **`tests/server/net/relay.test.ts:93`:** `{...hello, name}` spreads a function. Use `{...hello(), name}` so the test actually checks the free-text-name rejection.
- **`src/net/protocol.ts:65-68`:** command ids aren't checked against the catalog. Check them on the server before rebroadcasting, so they can't become a chat channel.
- **Ownership:** `package.json`, `pnpm-lock.yaml` and `tsconfig.json` belong to Lane 2. Hand commit 7dcacc1 to Lane 2. A `.dockerignore` is missing.
